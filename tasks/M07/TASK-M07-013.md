## Objective
دالة نقية `TruthAxis.Derive` تشتق الحالة الداخلية لمحور الحقيقة من قيمتين منفصلتين: السلوك الحالي (هل يوجد `REPENT_QUIT` بعد آخر ذنب دون `RELAPSE` بعده) والحقوق المعلقة (FR-W3)، فتُرجع إحدى الحالات الأربع `Honest`/`Persisting`/`ReformInProgress`/`Reformed` (PRD 7.11)، مع ضمان FR-X2 وFR-X3.

## Description
محور الحقيقة مدخل محدد النهاية ([TASK-M09-001](../M09/TASK-M09-001.md)) والضمير والحوارات ومدقق الاتساق ([TASK-M07-014](../M07/TASK-M07-014.md)). يُحسب ولا يُخزَّن كحالة مستقلة، فلا يمكن أن يختلف عن مصادره. FR-X2: `ReformInProgress` لا تُعامل كـ `Persisting` في أي مكان. FR-X3: أسماء الحالات داخلية، ولا يظهر نص يقول إن التوبة قُبلت أو إن الله غفر أو يتحدث عن الآخرة.

## Implementation Plan
1. `Simulation/Repentance/TruthState.cs`: enum `Honest, Persisting, ReformInProgress, Reformed`.
2. `Simulation/Repentance/TruthAxis.cs`:
   ```
   static TruthState Derive(RepentanceState rep, RightsLedger rights)
     if rep.lastWrongSeq == 0            → Honest
     stopped = rep.lastQuitSeq > rep.lastWrongSeq
     if !stopped                          → Persisting
     if rights.TotalOwed > 0              → ReformInProgress
     else                                 → Reformed
   ```
   "لا ذنوب معتبرة" = لا حدث `isWrongdoing` (جدول [TASK-M07-001](../M07/TASK-M07-001.md))؛ العتبة `minWrongdoingsForNotHonest` (افتراضي 1) في `moral_weights.json` تُضبط في الموازنة.
3. `RELAPSE` يجعل `lastWrongSeq > lastQuitSeq` تلقائياً (الذنب نفسه حدّث `lastWrongSeq`)، فلا يحتاج فرعاً خاصاً.
4. دالة ثانية `DeriveFromLog(IReadOnlyList<GameEvent>, MoralWeights)` تُسقط الحالتين من السجل ثم تستدعي `Derive` (لـ [TASK-M07-014](../M07/TASK-M07-014.md) وFR-J8).
5. `TruthFacts`: `truth.persisting` (bool، صحيح لـ `Persisting` فقط)، `truth.reforming` (bool لـ `ReformInProgress` أو `Reformed`)، `truth.honest`. لا تُكشف قيمة enum كنص.
6. قاعدة في `ContentValidator`: أي شرط سطر أو قاعدة عاقبة يستخدم `truth.*` بعامل `!=` أو بنفي `honest` وحده يُرفض برسالة "FR-X2: افصل ReformInProgress عن Persisting صراحة".
7. فحص FR-X3: جداول الترجمة لا تحوي أسماء الحالات الإنجليزية، ولا تُربط الحالات بمفاتيح عرض مباشرة؛ أسماء النهايات تُعرض من بيانات النهايات بعد المراجعة.

## Acceptance Criteria
- [ ] جدول اختبار يغطي: بلا ذنب ← `Honest`؛ ذنب بلا إقلاع ← `Persisting`؛ ذنب ← ندم فقط ← `Persisting`؛ ذنب ← إقلاع + مستحق > 0 ← `ReformInProgress`؛ ذنب ← إقلاع + رد كامل ← `Reformed`؛ إقلاع ← ذنب (انتكاس) ← `Persisting`؛ ذنب ← رد كامل بلا إقلاع ← `Persisting`.
- [ ] `Derive` و`DeriveFromLog` متطابقتان على 100 سيناريو عشوائي البذرة.
- [ ] الدالة نقية: استدعاؤها لا يغيّر أي حالة (اختبار لقطة قبل وبعد).
- [ ] `ContentValidator` يرفض شرطاً من نوع `truth.honest == false` يجمع الحالتين.
- [ ] لا يوجد `Honest|Persisting|ReformInProgress|Reformed` في أي جدول ترجمة.
- [ ] واجهة `Derive` موثقة لـ [TASK-M09-001](../M09/TASK-M09-001.md) (توقيع ثابت).

## Potential Issues
- تخزين الحالة كحقل منفصل "للأداء": ممنوع؛ الحساب O(1) من حالتين محفوظتين.
- ذنب بلا ضحية مالية (`FALSE_DESCRIPTION` بلا `amount`): يجعل الحالة غير `Honest` ولا يضيف حقاً؛ بعد الإقلاع تصبح `Reformed` مباشرة. موثق كسلوك مقصود للمراجع.
- العتبة > 1 تجعل غشاً واحداً "غير معتبر": قرار موازنة حساس يُعرض على المراجع قبل تغييره.
