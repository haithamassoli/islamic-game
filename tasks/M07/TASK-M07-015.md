## Objective
اختبار الحفظ T9 (PRD 7.15): رد حق جزئي، ثم حفظ، ثم تحميل؛ المستحق المتبقي لكل ضحية والحالة الداخلية (محور الحقيقة وآلة السلوك) بلا تغيير، مدمج في فئة `SaveTests` الإلزامية في CI.

## Description
T9 آخر اختبارات الحفظ ويحرس أهم ما في التوبة: أن الحقوق والحالة لا تضيع ولا تتضاعف عبر الحفظ (FR-S1، FR-S2). يستخدم رد الحق ([TASK-M07-009](../M07/TASK-M07-009.md)) وبنية اختبارات الحفظ ([TASK-M01-015](../M01/TASK-M01-015.md)) و`ScenarioScript` من [TASK-M06-005](../M06/TASK-M06-005.md). يعتمد عليه اختبار MVP الشامل [TASK-M13-001](../M13/TASK-M13-001.md) وبوابة P2/P3.

## Implementation Plan
1. `SaveTests.T9_PartialRestitution_SurvivesSaveLoad`: بذرة ثابتة؛ غش الزبونة (`amount=10`) وغش آخر لشخصية ثانية (`amount=4`)؛ ندم ← إقلاع؛ رد 4 للزبونة (`undisclosed`)؛ حفظ عند نقطة آمنة؛ تحميل. التحقق: `Owed(customer)=6`، `Owed(second)=4`، `TotalOwed=10`، `TruthState=ReformInProgress`، `BehaviorState=Quit`، طول السجل و`nextSeq` بلا تغيير، رصيد أسرة الزبونة بلا تغيير.
2. T1 على اللقطة نفسها: حفظ ← تحميل ← حفظ = بايت ببايت.
3. **T9b** رد جزئي بالتصدق عن مغادر: `CHARITY_ON_BEHALF` بمقدار 2 من 5 ← حفظ ← تحميل ← المتبقي 3، وحالة `Departed` محفوظة.
4. **T9c** الإكمال بعد التحميل: رد الباقي بعد التحميل يصل بالمستحق إلى 0 والحالة إلى `Reformed`، دون حدث مكرر.
5. **T9d** الانتكاس عبر الحفظ: إقلاع ← حفظ ← تحميل ← غش: `RELAPSE` واحد فقط، والحالة `Persisting`.
6. استدعاء `ConsistencyChecker` ([TASK-M07-014](../M07/TASK-M07-014.md)) بعد كل تحميل إن كان متاحاً (عبر `SimulationTestBase`).
7. وسم `[Category("SaveTests")]`؛ جدول CI يعرض T1–T9.
