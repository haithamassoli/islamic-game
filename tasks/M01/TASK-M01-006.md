## Objective
`GameClock` صنف C# عادي في `Simulation/Core`: زمن لعب بالدقائق الصحيحة، بيوم ودقيقة من اليوم، يتقدم بخطوة ثابتة، ويكشف حدود الفواصل الثابتة، وحالته قابلة للحفظ.

## Description
كل حدث يحمل `day` و`time` ([PRD 7.1](../../docs/PRD.md))، ودورة الشائعات تعمل على "فواصل ثابتة من زمن اللعبة" (FR-E6)، والأحداث المؤجلة لها `dueTime` (FR-E5)، وزمن اللعبة جزء من لقطة الحفظ (FR-S1). القاعدة 6 في [TECHNICAL_ARCHITECTURE §7](../../docs/TECHNICAL_ARCHITECTURE.md): خطوة زمن ثابتة ولا `deltaTime` داخل المحاكاة.

## Implementation Plan
1. `public sealed class GameClock` (namespace `IslamicGame.Simulation.Core`):
   - ثوابت: `MinutesPerDay = 1440`.
   - حالة واحدة: `long TotalMinutes` (0 = منتصف ليل اليوم 1).
   - مشتقات: `int Day => (int)(TotalMinutes / 1440) + 1`، `int MinuteOfDay => (int)(TotalMinutes % 1440)`.
   - `bool IsNewDay` صحيح بعد `Advance()` إذا عبرت الخطوة منتصف الليل.
   - `void Advance()` (+1 دقيقة = `TickMinutes`).
   - `bool IsBoundary(int intervalMinutes)` = `TotalMinutes % interval == 0` (لدورة الشائعات).
   - `long MinutesUntil(int minuteOfDay)` للانتقال إلى صباح الغد عند النوم (التقديم الفعلي يتم بخطوات `SimulationWorld.Step()` لتُنفَّذ الأحداث المستحقة).
2. بنية `GameTime` (readonly struct: `Day`، `Minute`، مقارنة، `ToString("D{day} HH:MM")` بـ InvariantCulture) لاستخدامها في الأحداث وسطور الضمير (FR-C2).
3. الحالة القابلة للحفظ: `ClockState { long totalMinutes }` مع `ToState()` و`static GameClock FromState(ClockState)`.
4. `GameClock(long startTotalMinutes)` لبدء اللعبة عند دقيقة صباحية يحددها المحتوى لاحقاً.
5. لا معامل سرعة ولا وقت حقيقي هنا؛ `GameRoot` في Runtime يحوّل الزمن الحقيقي إلى عدد خطوات ([TASK-M02-012](../M02/TASK-M02-012.md))، والإضاءة تستوفي بين الدقائق في العرض ([TASK-M02-010](../M02/TASK-M02-010.md)).

- [ ] `IsBoundary(30)` صحيح بالضبط 48 مرة في يوم كامل.
- [ ] `FromState(ToState())` يعطي ساعة مطابقة في كل الحقول.
- [ ] لا أعداد عشرية ولا `DateTime` ولا `UnityEngine` في الملفات.
- [ ] `GameTime.ToString` لا يتأثر بثقافة الجهاز العربية (أرقام لاتينية ثابتة في السجل).
