## Objective
مخططات بيانات المحتوى كأصناف C# في المحاكاة مع محمّل صارم: `LineDef` ([PRD 7.10](../../docs/PRD.md))، و`StorySegmentDef` ([PRD 7.13](../../docs/PRD.md))، و`SourceRecord` لسجل المصادر، و`ContentDatabase` يحمّلها ويتحقق من بنيتها، مع وسم صريح لما يُعد محتوى دينياً.

## Description
FR-D2: `Line { id, speaker, conditions[{fact, op, value}], priority, cooldown, once, vars[], textKey, audioKey, sourceIds[], reviewStatus }`. 7.13: `StorySegment { id, order, triggerLocation, narrationKey, audioKey, ayat[{surah, from, to}], hadithIds[], tafsirNotes[], unverifiedFlags[], reviewStatus }`. PRD 9: حقلا `sourceCheck` و`reviewStatus` منفصلان. هذه المخططات مدخل لبوابة البناء [TASK-M01-026](TASK-M01-026.md)، ومستورد المصحف [TASK-M01-027](TASK-M01-027.md)، ومحدد السطور [TASK-M01-029](TASK-M01-029.md)، و[TASK-M03-001](../M03/TASK-M03-001.md)، و[TASK-M04-001](../M04/TASK-M04-001.md)، و[TASK-M06-002](../M06/TASK-M06-002.md)، و[TASK-M08-002](../M08/TASK-M08-002.md).

## Implementation Plan
1. تعدادات: `ReviewStatus { draft, reviewed, approved, rejected }`، `SourceCheck { unverified, verified }`، `SourceKind { quran, hadith, fiqh, fatwa, tafsir }`، `ConditionOp { eq, ne, gt, ge, lt, le, has, not_has }`.
2. `LineDef` بحقول PRD 7.10 حرفياً، مع: `cooldown` بدقائق اللعب (`int`)، و`priority` (`int`)، و`ConditionDef { string fact; ConditionOp op; JValue value }` بقيم صحيحة/منطقية/نصية فقط، و`bool religious` صريح (سطر يذكر الله أو أجراً أو دليلاً، SR-12)، و`string approvedHash` (تملؤه البوابة، FR-Q3)، و`bool generic` لسطور الاحتياط (FR-D5)، و`string pool` لمجموعة السطور حسب الطباع (FR-D4).
3. `StorySegmentDef` بحقول 7.13 حرفياً، مع `AyahRef { int surah; int from; int to }` (لا حقل نص للآية إطلاقاً، FR-N2)، و`TafsirNote { string lineKey; string sourceId }`، و`UnverifiedFlag { string itemKey; string labelKey }` (S4: "رواية غير ثابتة")، و`sourceIds[]`، و`approvedHash`. المقطع ديني دائماً.
4. `SourceRecord` لأعمدة `content/sources/sources.csv` من [TASK-M00-006](../M00/TASK-M00-006.md)، و`SourceRegistry.LoadCsv(string text)` بمحلل CSV صغير (RFC 4180، UTF-8) دون مكتبة خارجية.
5. `ContentDatabase` (`Simulation/Core`): يحمّل نصوص JSON (Runtime يمرر نص TextAsset، والاختبارات والمحرر يمررون نص الملف) لـ `Content/Lines/*.json` و`Content/Story/*.json` بـ `MissingMemberHandling.Error`، ويتحقق بنيوياً: معرفات فريدة، و`order` فريد للمقاطع، و`textKey` غير فارغ، و`1 ≤ surah ≤ 114`، و`1 ≤ from ≤ to`، وكل `sourceIds` موجودة في السجل. المكتبات اللاحقة (الشخصيات، البضائع) تضيف مجموعاتها بالنمط نفسه.
6. توثيق المخططات بأمثلة JSON في [docs/DATA_ARCHITECTURE.md](../../docs/DATA_ARCHITECTURE.md) وتعريف "المحتوى الديني" في [docs/systems/CONTENT_PIPELINE.md](../../docs/systems/CONTENT_PIPELINE.md).

## Acceptance Criteria
- [ ] كل حقول PRD 7.10 و7.13 موجودة بالأسماء نفسها في JSON.
- [ ] لا يوجد في `StorySegmentDef` أو `LineDef` حقل يمكن أن يحمل نص آية (اختبار انعكاس على أسماء الحقول وأنواعها).
- [ ] حقل مجهول في JSON يرفض التحميل برسالة فيها الملف والمسار.
- [ ] تكرار `id` أو `order`، أو `surah=115`، أو `from>to`، أو `sourceId` غير موجود: كل منها يرفض التحميل.
- [ ] `SourceRegistry` يحمّل `content/sources/sources.csv` الفعلي بلا أخطاء ويحفظ النص العربي سليماً.
- [ ] عينة سطر غير ديني وعينة مقطع بإحالة صحيحة تُحمّلان بنجاح.
