## Objective
نموذج لاعب مؤقت محتشم (أصل مجاني بترخيص مسجل أو كبسولة مركبة) بحركات وقوف ومشي وجري وتفاعل، مربوط بسرعة `PlayerMotor` دون انزلاق ظاهر للقدمين.

## Description
النموذج (P1) بلا رسوم نهائية، لكن الأطفال في اختبار [TASK-M06-008](../M06/TASK-M06-008.md) يحتاجون شخصية مقروءة الاتجاه والحالة. الأصل مؤقت ويُستبدل في M10؛ لذلك الربط عبر Humanoid Avatar حتى يُعاد استعمال المتحكم الحركي. كل أصل خارجي يُسجل ترخيصه أولاً في سجل [TASK-M00-003](../M00/TASK-M00-003.md). اللباس محتشم حتى في النموذج المؤقت، وضوابط الشخصية الأنثى معلقة (SR-08)، فالنموذج المؤقت شخصية واحدة محايدة ولا يُبنى اختيار الجنس هنا.

## Implementation Plan
1. البحث عن نموذج Humanoid مجاني (مثلاً Unity Starter Assets أو أصل CC0) بلباس طويل محتشم؛ إن لم يوجد: كبسولة + رأس كروي + "صدرية" ملونة توضح الاتجاه.
2. تسجيل الأصل (الاسم، المصدر، الرخصة، الرابط) في سجل التراخيص قبل الاستيراد ([TASK-M00-003](../M00/TASK-M00-003.md)).
3. مقاطع حركة: `Idle`، `Walk`، `Run`، `Interact` (مد اليد 0.6ث)، `Talk_Idle`. لا حركات قتال.
4. `Art/Player/PlayerPlaceholder.controller`: Blend Tree بمعامل `Speed` (0 → 2.2 → 4.0) من `PlayerMotor.CurrentSpeed` ([TASK-M02-002](../M02/TASK-M02-002.md))، وTrigger `Interact`، وBool `InDialogue`.
5. `Runtime/Player/PlayerAnimatorBridge.cs`: يقرأ السرعة والحالة كل إطار ويكتب معاملات Animator. لا Root Motion (الحركة من المتحكم).
6. ضبط `Animator.speed` للمشي بحيث تتطابق خطوة المقطع مع 2.2 م/ث تقريباً.
7. تحديث `Player.prefab` ليحمل النموذج تحت جذر الكبسولة.

## Acceptance Criteria
- [ ] الأصل مسجل في سجل التراخيص برخصة تسمح بالاستخدام التجاري المجاني قبل أول commit له.
- [ ] الانتقال Idle ↔ Walk ↔ Run يتبع `CurrentSpeed` خلال ≤ 0.2ث، بلا انزلاق قدمين ملحوظ عند 2.2 و4.0 م/ث (مراجعة بصرية مسجلة).
- [ ] `Interact` يُشغَّل عند تنفيذ تفاعل، و`InDialogue` يثبت الشخصية في `Talk_Idle`.
- [ ] اللباس يغطي الجسد كاملاً (طويل وفضفاض)، ولا رموز أو كتابات على الملابس.
- [ ] حجم الأصل المضاف ≤ 15 ميغابايت في المستودع (عبر LFS للثنائيات).
