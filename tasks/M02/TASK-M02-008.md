## Objective
نظام تفاعل عام في Runtime: يكتشف أقرب هدف صالح أمام اللاعب، ويعرض تلميحه، وينفذه بزر `Interact`، بصنف أساس واحد `Interactable` ترثه نقاط الميزان والمورد والباب والسرير والشخصيات ونقاط السرد.

## Description
التفاعل "مصدر أفعال فقط" ([TECHNICAL_ARCHITECTURE 5](../../docs/TECHNICAL_ARCHITECTURE.md)): لا يغيّر حالة المحاكاة بنفسه، بل يستدعي مباشرة الصنف المسؤول (مثلاً الميزان يستدعي `TradeService`)، وكل فعل مهم يمر بخط FR-E4. يعتمد عليه: حوار الشخصيات ([TASK-M03-005](../M03/TASK-M03-005.md))، والشراء ([TASK-M04-005](../M04/TASK-M04-005.md))، والميزان ([TASK-M04-006](../M04/TASK-M04-006.md))، ونقاط السرد ([TASK-M08-002](../M08/TASK-M08-002.md)). لا يمنع أي خيار ولا يفرضه (FR-C4، DR-02): التفاعل متاح بنفس السهولة للفعل الأمين وغيره.

## Implementation Plan
1. `Runtime/Interaction/Interactable.cs` (abstract MonoBehaviour): `string PromptKey` (مفتاح ترجمة، مثل `interact.talk`)، `int Priority`، `float MaxDistance` (افتراضي 2.0م)، `virtual bool CanInteract(InteractionContext ctx)`، `abstract void Interact(InteractionContext ctx)`، `virtual string GetPromptArgs()` لمتغيرات مثل اسم الشخصية.
2. `InteractionContext` (struct): مرجع اللاعب، `PlayerMotor`، `InputRouter`، ووقت الطلب. لا مراجع لأنظمة المحاكاة؛ كل `Interactable` فرعي يأخذ ما يحتاجه من `GameRoot` عند الإنشاء.
3. `Runtime/Interaction/InteractionDetector.cs` على اللاعب: كل 0.1ث `Physics.OverlapSphereNonAlloc` (نصف قطر 2.5م، طبقة `Interactable`)، ثم ترشيح: المسافة ≤ `MaxDistance`، والزاوية مع اتجاه الكاميرا الأفقي ≤ 60°، وخط رؤية غير محجوب بـ `WorldStatic`، و`CanInteract`.
4. الاختيار: أعلى `Priority`، ثم أصغر زاوية، ثم أقرب مسافة، ثم `GetInstanceID` للثبات (لا تذبذب بين هدفين: هامش 10% قبل تبديل الهدف الحالي).
5. حدث C# محلي `CurrentChanged(Interactable)` يستهلكه عارض التلميح ([TASK-M02-009](../M02/TASK-M02-009.md))؛ مستهلك واحد معروف ولكن الربط عبر حدث لأن العارض في UI.
6. عند `Interact`: يُعطَّل الكشف حتى يعيد الهدف التحكم (`InteractionLock`) لمنع التنفيذ المزدوج، ويُشغَّل Trigger الحركة `Interact` ([TASK-M02-004](../M02/TASK-M02-004.md)).
7. أمثلة في هذه المهمة فقط: `DoorInteractable` (فتح/إغلاق بصري لبيت اللاعب)، و`DebugLogInteractable` لاختبار المشهد.
8. توثيق كيفية إضافة نوع جديد في [docs/systems/INTERACTION.md](../../docs/systems/INTERACTION.md).

## Acceptance Criteria
- [ ] هدفان على مسافتين 1.0م و1.8م أمام اللاعب: يُختار الأقرب؛ وعند أولوية أعلى للأبعد يُختار الأبعد.
- [ ] هدف خلف جدار `WorldStatic` أو خلف اللاعب (زاوية > 60°) لا يُختار.
- [ ] ضغطة `Interact` واحدة تستدعي `Interact` مرة واحدة فقط، حتى مع الضغط المتكرر السريع (10 ضغطات في ثانية).
- [ ] لا تذبذب: هدفان متساويان تقريباً لا يتبادلان أكثر من مرة في 2ث مع ثبات اللاعب.
- [ ] لا يوجد في `Runtime/Interaction` أي استدعاء لـ `DecisionLog` أو تعديل حالة محاكاة (فحص grep).
- [ ] تكلفة الكشف ≤ 0.1 مللي ثانية لكل فحص مع 20 هدفاً (Profiler).
