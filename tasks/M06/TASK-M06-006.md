## Objective
لوحة تطوير داخل اللعبة (نسخ التطوير والمحرر فقط) تعرض آخر أحداث السجل، ومعتقدات كل شخصية بمصادرها، وسلاسل انتقال الشائعات، والثقة والسمعة، لتشخيص المحاكاة ومراقبة جلسات الاختبار دون أن يراها الطفل.

## Description
أنظمة الإدراك والذاكرة والشائعات غير مرئية بطبيعتها (FR-M1، FR-R2). بلا أداة رؤية يصعب تفسير "لماذا اتُّهمت؟" أثناء [TASK-M06-008](../M06/TASK-M06-008.md) أو تصحيح عطل. اللوحة طبقة **عرض** قراءة فقط: تشترك في `DecisionLog.OnRecorded` وتقرأ حالة `SimulationWorld` ولا تغيّرها (PRD 8.2). لا تدخل البناء الإصداري إطلاقاً (S9: لا عداد أخلاقي ظاهر للاعب).

## Implementation Plan
1. `Runtime/UI/DevPanel/DevPanel.cs` محاط بـ `#if UNITY_EDITOR || DEVELOPMENT_BUILD`؛ يُفتح بمفتاح `F9` من Input Actions (خريطة `Debug` منفصلة لا تظهر في إعدادات اللاعب).
2. أربعة تبويبات (UI Toolkit أو IMGUI، الأسرع للتنفيذ):
   - **السجل:** آخر 200 حدث: `seq`، النوع، الفاعل، الهدف، اليوم/الوقت، `amount`، `witnessIds`، `causeEventIds`. تصفية بالنوع.
   - **المعتقدات:** اختيار شخصية ← جدول `claim`، `source`، `basisEventId`، `fromNpcId`، `hops`، `confidence` (بالألف)، `day`. تمييز المعتقد الخاطئ (`basisEventId` فارغ أو حدثه ليس للاعب).
   - **الشائعات:** لكل `basisEventId` سلسلة الانتقال كما سُجلت (`A ← B ← C`) مع اليوم.
   - **العلاقات:** `trust`/`affection` لكل شخصية، والسمعة المشتقة.
3. مصدر البيانات: دوال قراءة موجودة (`MemoryStore.BeliefsOf(npcId)`، `Relationships.Get(npcId)`)؛ إن لزمت دالة قراءة جديدة فهي `IReadOnly...` ولا تُرجع مراجع قابلة للتعديل.
4. زر "تصدير لقطة" يكتب JSON الحالي إلى `Application.persistentDataPath/dev_dumps/` لإرفاقه بتقارير الأعطال.
5. وضع الجلسة: لا شيء من اللوحة يظهر على شاشة الطفل؛ المُيسّر يفتحها بعد الجلسة أو على شاشة ثانية عبر نافذة المحرر `Window > IslamicGame > Dev Panel` (نفس الكود).
6. فحص CI: grep على بناء الإصدار يتأكد من عدم وجود نوع `DevPanel` (أو بناء إصداري يفشل إن وُجد مرجع خارج الشرط).
