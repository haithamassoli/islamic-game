## Objective
مستودع git على الفرع `main` جاهز لمشروع Unity: `.gitignore` يستثني ملفات Unity المولَّدة، و`.gitattributes` يرسل الأصول الثنائية إلى Git LFS ويضبط دمج YAML، وقرار مكتوب بشأن `.codex/` و`.mcp.json`، وأول commit نظيف.

## Description
المستودع موجود على `main` بلا أي commit، وفيه `.codex/` و`.mcp.json`. قواعد AGENTS.md §4 (Force Text، Visible Meta، الأصول الثنائية عبر LFS) وهيكل [D-012](../../planning/DECISIONS.md) (مشروع Unity في `unity/`) تحتاج إعداد git قبل [TASK-M01-001](../M01/TASK-M01-001.md). إن دخل ملف ثنائي إلى التاريخ بلا LFS فإزالته لاحقاً تحتاج إعادة كتابة التاريخ، ولذلك يسبق هذا الإعداد أي أصل.

## Implementation Plan
1. `git lfs version`؛ إن لم يوجد: `brew install git-lfs` ثم `git lfs install`.
2. `.gitignore` في الجذر بمسارات `unity/` صريحة: `unity/[Ll]ibrary/`، `unity/[Tt]emp/`، `unity/[Oo]bj/`، `unity/[Bb]uild/`، `unity/[Bb]uilds/`، `unity/[Ll]ogs/`، `unity/[Uu]ser[Ss]ettings/`، `unity/[Mm]emoryCaptures/`، `unity/[Rr]ecordings/`، وملفات IDE (`*.csproj`، `*.sln`، `*.suo`، `*.user`، `*.pidb`، `*.pdb`، `*.mdb`، `*.opendb`، `*.VC.db`، `.vs/`، `.idea/`)، وملفات النظام (`.DS_Store`)، ومخرجات البناء (`Builds/`، `*.apk`، `*.aab`، `*.app`)، ونتائج الاختبار (`results*.xml`)، و`__pycache__/`. **لا** يُستثنى `*.meta`.
3. `.gitattributes`:
   - `* text=auto eol=lf`، و`*.cs *.json *.csv *.yarn *.md *.py *.asmdef *.uxml *.uss text eol=lf`.
   - YAML Unity: `*.unity *.prefab *.asset *.mat *.anim *.controller *.overrideController *.physicMaterial *.mask *.playable *.lighting *.meta merge=unityyamlmerge eol=lf`.
   - LFS (`filter=lfs diff=lfs merge=lfs -text`): `*.fbx *.obj *.blend *.png *.jpg *.jpeg *.tga *.tif *.tiff *.psd *.exr *.hdr *.wav *.mp3 *.ogg *.aif *.aiff *.ttf *.otf *.mp4 *.mov *.zip *.unitypackage *.dll *.dylib *.so *.a`.
   - ملف المصحف الخام `content/quran/*.txt` نصي **خارج** LFS (لتُقرأ بصمته وفروقه مباشرة).
4. مشغّل الدمج `unityyamlmerge` إعداد محلي لا يُحفظ في المستودع: يُوثَّق أمره في `README.md` (`git config merge.unityyamlmerge.driver '"<Unity>/Contents/Tools/UnityYAMLMerge" merge -p %O %B %A %A'`).
5. فحص `.mcp.json` و`.codex/`: إن احتويا مسارات خاصة بالجهاز أو مفاتيح أو رموز وصول ← يُستثنيان في `.gitignore` ويُضاف `.mcp.json.example` منقّح؛ وإلا ← يُحفظان. يُسجَّل القرار وسببه في Notes وفي `README.md`.
6. `python3 tools/plan.py check` يجب أن ينجح، ثم أول commit: `TASK-M00-002: repository bootstrap` بكل وثائق التخطيط والأداة.
7. اختياري بموافقة المالك: إنشاء مستودع GitHub خاص ودفع `main` (يحتاجه CI في [TASK-M01-004](../M01/TASK-M01-004.md)).

## Acceptance Criteria
- [ ] `git lfs track` يعرض كل أنماط الأصول الثنائية المذكورة في الخطة.
- [ ] ملف `test.png` مؤقت بعد `git add` يظهر في `git lfs ls-files`، ثم يُزال قبل الـ commit.
- [ ] `git check-ignore -v unity/Library/x unity/Temp/x unity/UserSettings/x` يطابق القواعد الثلاث، و`git check-ignore unity/Assets/a.meta` لا يطابق شيئاً.
- [ ] `git check-attr merge unity/Assets/x.prefab` يعطي `unityyamlmerge`.
- [ ] قرار `.codex/` و`.mcp.json` مسجل مع سببه، ولا يوجد في التاريخ أي سر أو رمز وصول (`git log -p | grep -iE 'token|secret|api[_-]?key'` فارغ).
- [ ] أول commit موجود على `main`، و`git status` نظيف بعده، و`python3 tools/plan.py check` ينجح.

## Potential Issues
- حصة LFS المجانية في GitHub (تخزين ونقل محدودان) تنفد مع الصوت والنماذج: تُراقب، والبدائل (حصة مدفوعة أو مستضيف آخر) تُقرر عند الحاجة.
- إضافة نمط LFS بعد دخول ملفات ثنائية لا يحوّلها: لذلك الإعداد قبل أي أصل؛ وإن حدث فـ `git lfs migrate import` قبل أي push.
- `*.asset` ثنائي إن لم يُفعَّل Force Text: يُفعَّل في [TASK-M01-001](../M01/TASK-M01-001.md) قبل أول أصل.
- `*.dll` في LFS قد يُربك بعض الحزم المضمنة: الحزم تأتي من Package Manager لا من `Assets/`.
