## Objective
`HearsayEvaluator` يقرر لكل خبر مسموع: قبول، أو تأجيل الحكم، أو رفض، بحسب سمة `skeptic` وثقة السامع باللاعب ومعرفته المباشرة المناقضة وقوة الحافة مع الراوي؛ والمقبول يُضاف للذاكرة ويحدّث العلاقات مباشرة.

## Description
FR-M4: "السامع يقيّم الخبر: الشخصية `skeptic`، أو التي تثق باللاعب كثيراً، قد ترفضه أو تؤجل الحكم". مثال GAMEPLAY_LOOP §7: كبير السوق (`skeptic`) يؤجل الحكم. التأجيل حالة محفوظة: الخبر يُقبل إن جاء مؤيد مستقل، ويسقط بانتهاء المهلة.

## Implementation Plan
1. `EvaluationContext`: المرشح، سمات السامع، `trust` السامع تجاه الموضوع (من `Relationships`، [TASK-M05-008](TASK-M05-008.md))، معتقدات السامع المباشرة عن الأساس نفسه، قوة الحافة، `defenseScore` (0 حتى [TASK-M05-012](TASK-M05-012.md)).
2. درجة القبول بالألف *(مقترح)*: `600 + edgeStrength/4 − 300(skeptic) − max(0, trust−40)*5 (للادعاء السلبي) + max(0, −trust)*3 − defenseScore`.
3. قواعد حاسمة قبل الدرجة: معرفة مباشرة مناقضة (`WITNESS HONEST` على `basisEventId` نفسه) ← رفض؛ الخبر يطابق معتقداً موجوداً ← تقوية.
4. القرار: درجة ≥ 650 ← قبول؛ 350..649 ← تأجيل (`PendingHearsay` بمهلة يومين)؛ < 350 ← رفض. سحب واحد فقط من تيار `rumors` لحالة الحد (±50 حول العتبة)، لتبقى الحتمية والتنوع.
5. المؤجل: عند وصول مرشح ثانٍ لنفس `(listener, subject, claim, basis)` من راوٍ مختلف ← قبول بثقة الأعلى. المهلة تنتهي في `Tick` ← حذف بلا معتقد.
6. الرفض يُسجَّل في `toldTo` فلا يكرر الراوي نفسه المحاولة.
7. عند القبول: `MemoryStore.Add` ثم `Relationships.ApplyBelief(listener, belief)` استدعاءً مباشراً (مستهلك واحد).
8. ثقة المعتقد المقبول = ثقة المرشح × `score/1000` (محدودة بـ 1000).
