## Objective
`MemoryHandler` هو المعالج الأول في الخطوة 5 من FR-E4: يحوّل كل حدث مسجل إلى معتقدات للشهود (`WITNESS`) وللضحية عند الاكتشاف (`VICTIM`) حسب جدول قواعد ثابت، مع `LastProcessedSeq`، ويكشف للمعالجات اللاحقة ما أنشأه لكل `seq`.

## Description
FR-E4 الخطوة 5.1: "الذاكرة والمعتقدات (للشهود والضحية)". FR-E7: تجاهل `seq <= lastProcessedSeq`. FR-R2: السمعة لا ترى إلا المعتقدات؛ لذلك هذا المعالج هو البوابة الوحيدة بين السجل والمجتمع: غش بلا شهود ولا اكتشاف لا ينشئ معتقداً. الترتيب الكامل: Memory(1) ← MoralLedger(2) ← Repentance(3) ← Relationships/Reputation(4) ← Scheduling(5) ← StoryState(6).

## Implementation Plan
1. `Simulation/Memory/MemoryHandler.cs : ISimulationHandler` في الخانة 1 من القائمة الثابتة في `SimulationWorld`.
2. `Simulation/Memory/BeliefRuleTable.cs`: صفوف بيانات `{eventType, tagFilter, recipient: Witnesses|Actor|Target, subject: Actor|Target, claim, source, baseConfidence, significance}`:
   - `CHEAT_SCALE|CHEAT_MIXING|FALSE_DESCRIPTION` ← الشهود: `CHEATED` عن الفاعل، `WITNESS`، 800‰ *(مقترح)*، `Minor` لـ underweigh و`Major` لـ short_weight.
   - `TRADE_HONEST/sale` ← الشهود: `HONEST`، `WITNESS`، 400‰، `Minor`. (`purchase` بلا قاعدة الآن).
   - `CONSEQUENCE/victim_discovery` ← الفاعل (الضحية): `CHEATED` عن الهدف، `VICTIM`، 950‰، `Major`، `basisEventId` = أول `causeEventIds`.
   - `CONSEQUENCE/inspection_found` ← الفاعل (كبير السوق) والشهود: `CHEATED`، `WITNESS`، 1000‰، `Major`.
   - `CONSEQUENCE/home_weigh_ok` ← الفاعل: `HONEST`، `WITNESS`، 600‰، `Minor`.
   - صفوف `ACCUSED` و`CLEARED` و`MISTAKE` تضيفها 016 و015 و013.
3. لكل صف بترتيب الجدول، ولكل مستلم بترتيب Ordinal: `MemoryStore.Add` مع `day` و`basisEventId=seq` (ما لم يحدد الصف غيره) و`originSource=source`.
4. المستلم يجب أن يكون شخصية مسماة لها ذاكرة؛ الأسر الخلفية تُتجاهل بصمت.
5. تسجيل `createdBySeq[seq] = [beliefIds]` لمعالج العلاقات (الخانة 4) في الدورة نفسها.
6. لا عشوائية في هذا المعالج.
