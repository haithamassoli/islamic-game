## Objective
قرار مكتوب بالمنصة التالية بعد macOS (WebGL أو iOS أو Android) مبني على أرقام تقارير P0 وP2 وأداء MVP، بمصفوفة معايير موزونة، مسجل كقرار جديد في DECISIONS.

## Description
PRD 11 (P4): "قرار الويب أو الجوال حسب تقارير P0 وP2، وتحكم باللمس، ثم Windows"، وبوابتها "أهداف الأداء لكل منصة". المخاطر (PRD 13): أداء Unity على الويب والجوال يُقاس في P0 وP2 قبل قرار P4. المهمة قرار فقط؛ لا تنفيذ نقل. أولوية منخفضة ولا تمنع MVP.

## Implementation Plan
1. جمع المدخلات: `docs/reports/PORTABILITY_P0.md` (TASK-M01-023)، و`docs/reports/PERF_VS_WEB_MOBILE.md` (TASK-M11-004)، و`docs/reports/PERF_MVP_M1.md` (TASK-M13-002)، وقرار عرض العربية (TASK-M01-022)، وملخص بلاغات الإطلاق (TASK-M13-010).
2. مصفوفة المعايير بأوزان تُعتمد قبل التقييم: الأداء المتوقع بعد تحسين معقول، وحجم التنزيل، وعرض العربية والرسم العثماني وحجم ICU، وتخزين الحفظ (IndexedDB مقابل ملفات)، والإدخال (لمس مقابل لوحة مفاتيح)، والوصول للجمهور (الأطفال والأسر)، وسياسات المتاجر لتطبيقات الأطفال (S13: بلا إعلانات أو مشتريات)، وكلفة التطوير والصيانة.
3. تقدير الجهد لكل منصة: ما يلزم للوصول لهدف الأداء (من توصيات TASK-M11-004)، وتحكم اللمس (TASK-M14-002)، وتنفيذ `ISaveStorage` إن لزم.
4. أهداف الأداء المقترحة للمنصة المختارة (مثل 30 إطاراً ثابتاً على الجهاز المرجعي) لتصبح بوابة P4.
5. جلسة قرار مع مالك المنتج والمسؤول التقني؛ تسجيل القرار وأسبابه الرقمية والبدائل المرفوضة.
