## Objective
قائمة رئيسية RTL (لعبة جديدة، متابعة، تحميل، إعدادات، خروج) وشاشة ثلاث خانات حفظ تعرض ملخص كل خانة وتدعم الحذف واستعادة النسخة الاحتياطية، فوق `SaveManager` الموجود.

## Description
FR-S5: حفظ تلقائي وعند النوم، و3 خانات، ونسخة احتياطية من الحفظ السابق. FR-S6: التخزين خلف `ISaveStorage`. `SaveManager` من [TASK-M01-013](../M01/TASK-M01-013.md). المكونات من [TASK-M10-001](../M10/TASK-M10-001.md). S13: لا حسابات ولا شبكة، فلا "تسجيل دخول" ولا "سحابة".

## Implementation Plan
1. `Scenes/MainMenu.unity` مع خلفية من السوق النهائي (لقطة ثابتة أو كاميرا بطيئة) وبيئة صوتية بلا معازف ([TASK-M10-010](../M10/TASK-M10-010.md)).
2. `Runtime/UI/MainMenu/MainMenuScreen.cs`: "متابعة" تحمّل أحدث خانة (حسب طابع الحفظ)، وتختفي إن لم توجد خانات.
3. `SaveSlotSummary` (يُكتب في رأس ملف الحفظ دون فتح اللقطة كاملة): `slotIndex`، اليوم واسم المكان (مفتاح)، اسم الشخصية، زمن اللعب، علامة `afterEnding`، طابع الوقت الحقيقي للعرض فقط (خارج المحاكاة).
4. `SaveSlotsScreen`: ثلاث بطاقات؛ خانة فارغة ⇒ "لعبة جديدة هنا"؛ ممتلئة ⇒ تحميل/حذف (حوار تأكيد)؛ لعبة جديدة فوق خانة ممتلئة ⇒ تأكيد الاستبدال.
5. خانة تالفة: يكتشفها `SaveManager` (فشل تحقق) فتظهر بحالة "تالفة" مع خيار "استعادة النسخة السابقة" إن وُجدت (FR-S5)، ولا يُحذف شيء آلياً.
6. "لعبة جديدة" ⇒ إنشاء الشخصية ([TASK-M10-005](../M10/TASK-M10-005.md)) ⇒ بطاقة الخيال (S5) ⇒ اللعب.
7. الخروج يعرض تأكيداً فقط إن كان حفظ قيد الكتابة.
8. كل النصوص بمفاتيح `menu.*`، والتنقل الكامل بلوحة المفاتيح والذراع.

## Acceptance Criteria
- [ ] الخانات الثلاث تُعرض بملخصاتها خلال ≤ 300 ms دون تحميل اللقطات كاملة.
- [ ] "متابعة" تحمّل الخانة الأحدث، وتختفي عند غياب الخانات.
- [ ] حذف خانة يتطلب تأكيداً ويحذف ملفها ونسختها الاحتياطية فقط.
- [ ] خانة تالفة اصطناعياً (بايتات عشوائية) تظهر "تالفة" ويمكن استعادة نسختها الاحتياطية وتحميلها.
- [ ] إضافة `SaveSlotSummary` لا تكسر T1 وT7 (ترحيل الإصدار الأقدم ينجح).
- [ ] صفر نص ثابت، والتخطيط RTL كاملاً.
