## Objective
بناء macOS داخلي موسوم بإصدار للشريحة العمودية، مع قائمة فحص مكتوبة ومكتملة تثبت جاهزيته للعرض الداخلي واختبار اللعب، وقابلة لإعادة الاستخدام في إصدار MVP (TASK-M13-008).

## Description
بوابة P2 تحتاج بناءً واحداً معروفاً تُنسب إليه كل النتائج (الأداء، والتدقيق الديني، واختبار اللعب). البناء داخلي فقط (لا توزيع عام، PRD 3)، لكنه يمر بنفس شروط الإصدار: البوابة الدينية (FR-Q1، FR-Q2)، وعدم وجود شبكة أو جمع بيانات (S13)، وتعطيل أدوات التطوير، ونجاح اختبارات الحفظ المتاحة.

## Implementation Plan
1. توسيع `BuildScripts` (TASK-M01-005) بأمر `BuildVerticalSlice` يضبط define `IG_RELEASE`، ويستبعد لوحة التطوير (TASK-M06-006) ومدقق الاتساق، ويكتب `build_info.json` (الإصدار، git SHA، تاريخ البناء، بصمة قائمة المحتوى الديني).
2. ترقيم الإصدار `0.2.0-vs` (مقترح) ووسم git `vs-0.2.0`.
3. قائمة فحص `VS_BUILD_CHECKLIST.md` بخانات: سجل بوابة المحتوى بلا أخطاء، وتطابق بصمة القائمة مع قائمة TASK-M11-005 الموقعة، ونجاح اختبارات EditMode وPlayMode، ونجاح T1–T9 المتاحة في CI، وتقرير الأداء (TASK-M11-003) مرفق، ولا اتصالات شبكة، ولا ملفات خارج مجلد الحفظ، ولا لوحة تطوير ولا علامة "مسودة".
4. فحص الشبكة: تشغيل البناء 10 دقائق مع مراقبة `nettop -p <pid>` أو `lsof -i` وتسجيل صفر اتصالات.
5. ثلاث تشغيلات كاملة يدوية (مسار أمين، غش ثم توبة، غش منكشف) دون انهيار، مع حفظ وتحميل في منتصف كل منها.
6. التوقيع: توقيع محلي ad-hoc كافٍ للاستخدام الداخلي؛ توقيع Developer ID والتوثيق مؤجلان إلى TASK-M13-008، ويُوثق ذلك.
7. أرشفة البناء `IslamicGame-VS-0.2.0-<sha>.zip` مع بصمة SHA-256 في مكان تخزين الفريق (خارج git، لا LFS للبناءات).

## Acceptance Criteria
- [ ] `BuildVerticalSlice` يعمل من سطر الأوامر batchmode وينتج تطبيق `.app` يفتح على macOS Apple Silicon.
- [ ] `build_info.json` يحوي الإصدار وgit SHA وبصمة القائمة الدينية، وتطابق البصمة القائمة الموقعة في TASK-M11-005.
- [ ] كل بنود القائمة مؤشرة مع دليل (رابط تقرير، أو مخرج أمر، أو لقطة).
- [ ] صفر اتصالات شبكة خلال 10 دقائق لعب.
- [ ] 3 تشغيلات كاملة بلا انهيار، وحفظ وتحميل في منتصف كل منها يكمل الشريحة.
- [ ] البناء يرفض الإنشاء إذا فشلت البوابة الدينية (تجربة سلبية موثقة).
