## Objective
نموذج بيانات `ReviewCard` وبانٍ نقي `JourneyReviewBuilder` يجعلان مخالفة FR-J1..FR-J5 مستحيلة بنيوياً: لا بطاقة بلا `evidenceEventIds` غير فارغة، ولا رقم بلا أحداث مصدر، ولا ربط سببي إلا عبر `causeEventIds` أو سلسلة شائعة مسجلة.

## Description
PRD 7.12: المراجعة تُبنى فقط من وقائع حدثت (FR-J1)، كل بطاقة تحمل `evidenceEventIds[]` غير فارغة والقالب بلا بيانات لا يُعرض (FR-J2)، لا نتائج افتراضية (FR-J3)، الأرقام من الحقول المسجلة والسببية فقط عبر `causeEventIds` أو سلسلة الشائعة كما سُجلت (FR-J4)، وأحداث الحياة لا تُربط بذنب (FR-J5). يعتمد على `GameEvent` ([TASK-M01-008](../M01/TASK-M01-008.md)) وعلى سجل انتقال الشائعات في المعتقدات ([TASK-M05-005](../M05/TASK-M05-005.md): `fromNpcId`، `hops`، `day`، `basisEventId`).

## Implementation Plan
1. `Simulation/Journey/ReviewCard.cs`: `{ string id; string templateId; long[] evidenceEventIds; ReviewNumber[] numbers; CausalLink[] links; ReviewVar[] vars (مرتبة بالمفتاح Ordinal); string textKey; string lessonContentId?; long sortSeq }`.
2. `ReviewNumber { string key; long value; long[] sourceEventIds; NumberRule rule }` حيث `NumberRule ∈ {SumAmount, Count}` فقط. القيمة تُحسب داخل المصنع من الأحداث، ولا مُنشئ عام يقبل قيمة جاهزة.
3. `CausalLink` يُنشأ فقط عبر: `CausalLink.FromCauseIds(GameEvent effect)` (يقرأ `causeEventIds`) أو `CausalLink.FromRumorChain(RumorHop[])`. `RumorHop {fromNpcId, toNpcId, day, beliefId}` يُستخرج من معتقدات محفوظة فقط.
4. `ReviewCardFactory.TryCreate(templateId, evidence, ...)` يرجع `null` إن كانت الأدلة فارغة أو أي معرّف غير موجود في السجل.
5. قاعدة FR-J5 داخل المصنع: إن احتوت `evidenceEventIds` حدثاً `LIFE_EVENT` مع أي حدث ذنب (`CHEAT_*`، `FALSE_DESCRIPTION`، `RELAPSE`) يُرفض الإنشاء، و`CausalLink` لا يقبل `LIFE_EVENT` طرفاً مع ذنب.
6. `JourneyReview { EndingId endingId; long uptoSeq; ReviewCard[] cards }`؛ `JourneyReviewBuilder.Build(ReviewContext ctx)` دالة نقية، و`ReviewContext` يجمع قراءةً فقط: السجل حتى `uptoSeq`، والمعتقدات، ودفتر الحقوق، وحالات الشخصيات المحفوظة.
7. الترتيب حتمي: `sortSeq` (أول دليل) ثم `templateId` Ordinal. الحد الأقصى للبطاقات من ملف إعداد (الشريحة: 8).
8. المراجعة لا تُحفظ كنص؛ يكفي `uptoSeq` لإعادة بنائها بالنتيجة نفسها (FR-S2).

## Acceptance Criteria
- [ ] لا يمكن إنشاء `ReviewCard` بأدلة فارغة أو بمعرّف غير موجود (الاختبار يحاول ويحصل على `null`).
- [ ] لا مُنشئ أو خاصية عامة تقبل قيمة رقم جاهزة؛ `ReviewNumber.value` = مجموع `amount` أو عدد الأحداث المصدر دائماً.
- [ ] `CausalLink` لا يُنشأ إلا من `causeEventIds` أو `RumorHop` مستخرجة من معتقدات (فحص انعكاسي لمنشئات النوع).
- [ ] بطاقة تجمع `LIFE_EVENT` مع حدث غش تُرفض.
- [ ] بناء المراجعة مرتين على السجل نفسه يعطي JSON متطابقاً بايتاً ببايت.
- [ ] `Simulation/Journey` بلا أي مرجع لـ `UnityEngine`.
- [ ] سلسلة شائعة من 3 قفزات تُستعاد بأسماء وأيام صحيحة من المعتقدات المحفوظة بعد حفظ وتحميل.
