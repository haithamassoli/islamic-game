# أهداف الأداء والميزانيات (Performance Targets)

المرجع: [PRD 8.5](PRD.md) (60 إطاراً في الثانية على Mac M1 بإعدادات متوسطة؛ أهداف الويب والجوال تُقاس في P0 وP2)، وPRD 12 (معيار نجاح MVP)، وPRD 13 (خطر أداء الويب والجوال)، و[TECHNICAL_ARCHITECTURE.md](TECHNICAL_ARCHITECTURE.md).

**حالة الأرقام:** هدف 60 إطاراً على M1 **ملزم** من PRD. كل الميزانيات الأخرى أدناه **مؤقتة**: نقطة بداية للمراجعة، تُثبت أو تُعدل بالقياس في [TASK-M11-003](../tasks/M11/TASK-M11-003.md) (Mac) و[TASK-M01-023](../tasks/M01/TASK-M01-023.md) و[TASK-M11-004](../tasks/M11/TASK-M11-004.md) (الويب والجوال). أي تعديل يُكتب هنا مع رابط تقرير القياس.

## 1. الهدف الملزم: Mac M1، إعدادات متوسطة
| المقياس | الهدف |
|---|---|
| زمن الإطار | 16.6 ms (60 fps) في السوق وقت الذروة، **p95 ≤ 16.6 ms** على مسار القياس |
| أسوأ إطار مقبول | ≤ 33 ms خارج الحفظ ونقاط التحميل، بلا تقطع متكرر |
| الدقة | دقة شاشة M1 الأصلية مع مقياس عرض URP حسب إعداد "متوسط" (يُعرّف في [TASK-M10-004](../tasks/M10/TASK-M10-004.md)) |

"إعدادات متوسطة" تُعرَّف كملف URP Asset مسمى (`URP_Medium`) يُحفظ في `Settings/`، فلا يتغير معنى الهدف بين القياسات.

## 2. ميزانيات الرسوم (مؤقتة، M1 متوسط)
| البند | الميزانية |
|---|---|
| Batches (Draw calls) | ≤ 1,500 |
| SetPass calls | ≤ 250 |
| مثلثات مرئية | ≤ 1.5 مليون |
| الشخصيات المتحركة المرئية | 12 + الزحام المحاكى (عدد يحدده [TASK-M03-004](../tasks/M03/TASK-M03-004.md))، مع LOD |
| الأضواء في الوقت الحقيقي | ضوء اتجاهي واحد بظلال + أضواء محلية مخبوزة أو محدودة |
| المعالجة اللاحقة | ميزانية GPU ≤ 2 ms (Bloom/Tonemapping/Color grading فقط) |
| الشاشة الكاملة للواجهة | ≤ 1 ms CPU لبناء الواجهة في الإطار العادي |

## 3. ميزانيات CPU للمحاكاة (مؤقتة)
المحاكاة صغيرة (12 شخصية، آلاف الأحداث)، والأداء ليس فيها ([TECHNICAL_ARCHITECTURE 10](TECHNICAL_ARCHITECTURE.md)). الميزانيات لمنع الانحدار:

| العملية | الميزانية |
|---|---|
| `SimulationWorld.Step()` العادي | ≤ 0.5 ms متوسطاً |
| `DecisionLog.Submit` بكامل FR-E4 (حدث واحد مع المعالجات الست) | ≤ 1 ms |
| `RumorSystem.Tick` (12 شخصية، حتى 2,000 معتقد) | ≤ 2 ms أسوأ حالة؛ يقع على فاصل ثابت لا كل إطار |
| `Memory.DecayDay` + اللفة اليومية | ≤ 5 ms مرة في اليوم (مخفية بانتقال الصباح) |
| `JourneyBuilder.Build` + `JourneyVerifier` | ≤ 200 ms مرة عند النهاية |
| تخصيص الذاكرة (GC) في الإطار العادي | 0 بايت في `Step` بلا أحداث؛ لا LINQ في المسارات الساخنة |

## 4. الذاكرة والحفظ (مؤقتة)
| البند | الميزانية |
|---|---|
| ذاكرة العملية على macOS | ≤ 2.5 GB |
| النسيج (Textures) | ≤ 1 GB |
| الصوت المحمّل | ≤ 150 MB (التسجيلات الطويلة Streaming) |
| حجم ملف الحفظ | ≤ 5 MB بعد 30 يوم لعب (تقدير: ~10,000 حدث × ~250 بايت + المعتقدات) |
| زمن الحفظ (تسلسل + كتابة ذرية) | ≤ 200 ms على M1، مع مؤشر الحفظ التلقائي |
| زمن التحميل من القائمة | ≤ 5 s حتى التحكم، منها ≤ 500 ms لاستعادة اللقطة |

اختبار التحمل في [TASK-M13-001](../tasks/M13/TASK-M13-001.md) يولّد سجلاً طويلاً ببذرة ثابتة ويقيس الحجم والزمن. إن تجاوز الحجم الميزانية: ضغط gzip للملف (مع بقاء T1 على البايتات غير المضغوطة) قبل أي تغيير في المخطط ([SAVE_SYSTEM.md](SAVE_SYSTEM.md)).

## 5. الويب والجوال (مؤقتة، للقرار لا للإطلاق)

| WebGL (Chrome وSafari على لابتوب متوسط) | ≥ 30 fps على مشهد P0، ثم على الشريحة | ≤ 1 GB heap | تحميل أولي ≤ 50 MB مضغوطاً (Brotli) قبل المحتوى الصوتي | [TASK-M01-017](../tasks/M01/TASK-M01-017.md)، [TASK-M11-004](../tasks/M11/TASK-M11-004.md) |

- التقرير المجمع: [TASK-M01-023](../tasks/M01/TASK-M01-023.md) (يُكتب في `docs/reports/PORTABILITY_P0.md`).

## 6. إجراء القياس
1. **البناء:** Development Build مع Autoconnect Profiler للقياس التفصيلي، و**Release Build** للأرقام النهائية (لا تُقارن أرقام Editor أبداً).
2. **المشهد والمسار:** مسار كاميرا ثابت مسجل (`PerfRoute`) في السوق وقت الذروة، بحالة لعب محملة من ملف حفظ ثابت (`perf_market_peak.json`) ببذرة ثابتة، فيتكرر الحمل نفسه في كل قياس.
3. **الأدوات:** Unity Profiler (CPU/GPU/Rendering)، وProfile Analyzer لمقارنة القياسات، وMemory Profiler للذاكرة، وFrame Debugger للـ Batches، وأدوات Xcode Instruments عند الحاجة.
4. **العينات:** 3 تشغيلات × 120 ثانية بعد 30 ثانية إحماء؛ يُسجل المتوسط وp95 وp99 وأسوأ إطار، وحرارة الجهاز (M1 بلا مروحة في بعض الطرازات: تشغيل على الكهرباء وبعد تبريد).
5. **المحاكاة بلا رسوم:** اختبارات EditMode بفئة `[Category("Perf")]` تشغل سيناريو ثابت البذرة وتقيس `Step` و`Submit` و`Tick` بـ `Stopwatch`، وتفشل عند تجاوز ضعف الميزانية (هامش لأجهزة CI). لا تعمل في كل commit بل ليلياً أو يدوياً.
6. **التوثيق:** كل قياس تقرير في `docs/reports/PERF_<platform>_<date>.md`: الإصدار، والجهاز، والإعداد، والأرقام، والمقارنة بالميزانية، والانحرافات وسببها.

## 7. ترتيب أولويات التحسين
الرسوم أولاً (Batching، GPU Instancing للزحام، LOD، Occlusion Culling للأحياء، ضغط النسيج)، ثم الذاكرة (Streaming للصوت، أحجام النسيج)، ثم المحاكاة فقط إن ظهرت في Profiler. ممنوع إدخال ECS أو تعدد خيوط في المحاكاة لأغراض الأداء دون قياس يثبت الحاجة وقرار جديد (D-004).
