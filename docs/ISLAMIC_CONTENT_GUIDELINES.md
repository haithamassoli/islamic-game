# الضوابط الشرعية للمحتوى (ISLAMIC_CONTENT_GUIDELINES)

> مسؤولية هذه الوثيقة: **الضوابط الشرعية الملزمة وطريقة تطبيقها**: القيود S1–S13 عملياً، وهرمية المصادر، وخط المرحلتين `sourceCheck`/`reviewStatus`، والأدوار، وبوابات المراجعة في كل مرحلة، وإضافة المسائل المعلقة، ووسم Needs Verification، والفصل بين البيانات الدينية والسيناريوهات الخيالية. هذه الوثيقة **ملزمة** لكل بشر ووكيل. مصدرها [PRD §2 و§9 و§10](PRD.md) و[AGENTS.md §8](../AGENTS.md)، وعند التعارض يفوز PRD. قواعد الكتابة الأسلوبية في [NARRATIVE_DESIGN.md](NARRATIVE_DESIGN.md).

## 1. النطاق: ما هو "المحتوى الديني"؟
كل عنصر مما يلي يمر بخط المرحلتين (القسم 4) قبل دخول البناء (S12، FR-Q1):

| النوع | أمثلة | أين يعيش |
|---|---|---|
| آية | إحالات المقاطع، آية في المراجعة | `ayat[{surah, from, to}]`؛ النص مستخرج من ملف المصحف (FR-N2) |
| حديث | ما في PRD §9.1 فقط حتى الآن | سجل المصادر، مع المصدر والرقم والدرجة (FR-Q2) |
| حكم أو فتوى | التصدق عن صاحب الحق المتعذر الوصول إليه (FR-W3) | سجل المصادر |
| سرد قصة | نص الراوي لكل مقطع | `StorySegment.narrationKey` |
| سطر ضمير أو إغراء | كل سطور الصوتين الداخليين | `Line` بمتحدث `conscience` أو `temptation` |
| دليل أو درس في مراجعة الرحلة | نصوص FR-J7 | قوالب `Journey/` |
| نصوص مسائل معلقة | التوبة (SR-11)، رد الحقوق (SR-02، SR-03)، النهايات | `Lines/`، `Endings/` |
| نص إطار ديني | بطاقة الانتقال (F5)، صفحة التعريف | مفاتيح ترجمة |
| قرار بصري أو صوتي ذو حكم | لباس الشخصيات، الأنثى (SR-08)، الأصوات (S11)، التلاوة، عرض الخاتمة (SR-04) | مهام فنية وصوتية بمراجعة شرعية |

**عند الشك: العنصر ديني.**

## 4. خط المرحلتين
الحقلان وقيمهما في PRD §9. سير الحالة:

```
sourceCheck:   unverified ──(مطابقة موثقة مع مصدر أصلي)──▶ verified
reviewStatus:  draft ──▶ reviewed ──▶ approved
                  └────────────┴──────▶ rejected
أي تعديل على عنصر approved أو verified ──▶ reviewStatus=draft (FR-Q3)
```

| القاعدة | التفصيل |
|---|---|
| البناء | يدخل فقط `sourceCheck=verified` **و** `reviewStatus=approved` معاً (FR-Q1). |
| الفحص الآلي | يفشل البناء عند: عنصر ديني لا يحقق الشرطين، حديث بلا مصدر ورقم ودرجة، آية بلا إحالة (FR-Q2، [TASK-M01-026](../tasks/M01/TASK-M01-026.md)). |
| التعديل | يعيد العنصر إلى `draft` ويبطل تسجيله الصوتي (FR-Q3، [AUDIO_DESIGN §6](AUDIO_DESIGN.md)). |
| التصدير والاستيراد | جدول يقرؤه المراجع غير المبرمج، ثم استيراد ملاحظاته وقراراته (FR-Q4، [TASK-M08-008](../tasks/M08/TASK-M08-008.md)). |
| المسائل المعلقة | الميزة تعمل بسلوكها الافتراضي المحايد حتى الحسم (FR-Q5، PRD §10). |
| عنصر بلا أي عزو (`sourceIds` فارغ، مثل سطر ضمير لا يستشهد) | تمثيل `sourceCheck` له يُحدد في مخطط [TASK-M01-025](../tasks/M01/TASK-M01-025.md). **الافتراض الأشد حتى ذلك الحين:** يحتاج الشرطين كغيره، ولا يُعدّ خلوه من العزو تحققاً. |
| النماذج الأولية | السطور المؤقتة في P1 غير دينية ولا تُشحن ([TASK-M06-002](../tasks/M06/TASK-M06-002.md)). |

**حقول السجل لكل عنصر *(مقترح، يُثبَّت في [TASK-M00-006](../tasks/M00/TASK-M00-006.md) و[TASK-M01-025](../tasks/M01/TASK-M01-025.md))*:** `id`، `type`، `reference` (سورة:آية أو مصدر:رقم)، `grade`، `sourceCheck`، `checkedBy`، `checkedAgainst` (المصدر الأصلي المطابَق)، `reviewStatus`، `reviewer`، `reviewDate`، `relatedSR`، `notes`.

## 7. إضافة مسألة شرعية جديدة (SR)
تنشأ المسألة متى ظهر سؤال حكم لا تحسمه PRD §2 ولا مسألة قائمة (مثال محتمل: تسجيل الأصوات الأنثوية، [AUDIO_DESIGN §5](AUDIO_DESIGN.md)).

1. **قبل بناء الميزة** أضف صفاً في سجل المسائل المعلقة `content/sharia/pending_register.csv` ([TASK-M00-007](../tasks/M00/TASK-M00-007.md)) بالمعرّف التالي (`SR-14`، ثم `SR-15`…؛ لا يُعاد استخدام رقم).
2. الحقول: `id`، المسألة، أين تُستخدم (FR-* أو مهمة)، **السلوك الافتراضي المحايد**، الحالة (`open`)، تاريخ الفتح، من فتحها.
3. **السلوك الافتراضي المحايد** يحقق واحداً على الأقل: الميزة معطلة، أو مبنية ونصوصها لا تُشحن، أو سلوك واحد لكل اللاعبين بلا ادعاء ديني. لا يجوز افتراض الجواز.
4. أنشئ مهمة مراجعة (`Type: Religious Review`) واربطها بمهمة الميزة في `Dependencies` إن كانت تمنعها.
5. اقترح على مالك PRD إضافة المسألة إلى PRD §10 (الوكيل لا يعدّل PRD).
6. عند الحسم: يسجّل المراجع القرار ومصدره في السجل، وتُحدَّث الميزة بمهمة جديدة. [TASK-M13-005](../tasks/M13/TASK-M13-005.md) يتحقق أن لا ميزة مفعّلة دون حسم.

|---|---|
| أي إحالة أو عزو أو درجة لم تُطابق مع مصدر أصلي | `sourceCheck=unverified` في البيانات، و**Needs Verification** بجانبه في الوثائق والمهام |
| إحالات القرآن في PRD (F4، §9.1) | تبقى **Needs Verification** حتى تُطابق آلياً مع ملف المصحف |
| شروط التوبة (النووي، رياض الصالحين) | **Needs Verification** (PRD §9.1) |
| مصدر يقترحه كاتب أو وكيل | يُكتب مقترحاً موسوماً، ولا يُستخدم قبل التحقق |

- الوسم لا يُزال إلا بتغيير `sourceCheck` إلى `verified` مع ذكر المصدر المطابَق.
- `verified` لا يعني الاعتماد: كل بنود PRD §9.1 `draft`، وحديث "التاجر الصدوق الأمين" **لا يُستخدم** (SR-06).
- لا يُضاف في هذه الوثيقة أو غيرها أي آية أو حديث أو فتوى خارج PRD §9.1 دون المرور بالسجل.

## 9. الفصل بين البيانات الدينية والسيناريوهات الخيالية
| الطبقة | المكان | المحتوى | من يعدّله |
|---|---|---|---|
| مصادر دينية | `content/sources/` | سجل المصادر وحالاتها | فريق المحتوى والمراجع |
| المسائل المعلقة | `content/sharia/` | سجل SR | المراجع (الحسم)، والكل (الإضافة) |
| المصحف | `content/quran/` | ملف المصحف الخام وبصمته | لا يُعدَّل؛ يُستبدل بإصدار موثق فقط |
| جداول المراجعة | `content/review/` | صادر ووارد المراجع (FR-Q4) | الأداة والمراجع |
| بيانات اللعبة | `unity/Assets/_Project/Content/` | شخصيات، بضائع، سطور، حوارات، مقاطع، نهايات، قوالب مراجعة | الكتّاب والمصممون |

**قواعد الفصل:**
- بيانات اللعبة **تحيل** إلى العناصر الدينية بالمعرّف (`sourceIds`، `ayat`) ولا تنسخ نصها. نص الآيات مولَّد من `content/quran/` بأداة الاستيراد ولا يُعدَّل يدوياً.
- السيناريوهات الخيالية (أحداث البلدة، حوارات الشخصيات، الأسماء، الأماكن) لا تحمل `sourceIds` ولا تُقدَّم كخبر ديني. **سطر متحدثه شخصية من البلدة ومعه `sourceIds` غير فارغ = فشل في البناء** (F3).
- المتحدثون المسموح لهم بالاستشهاد: الراوي، والضمير، ونصوص مراجعة الرحلة، والإغراء لا يستشهد *(مقترح: يُفرض في المدقق)*.
- اعتماد سيناريو خيالي لا يعتمد النص الديني المرتبط به، والعكس. كل منهما يُراجع بحالته.
- الأسماء الخيالية لا تُطابق أسماء أنبياء أو صحابة أو شخصيات من قصة مدين.
